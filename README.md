# Restaurant Management System

TypeScript, Express, PostgreSQL, Argon2 password hashing, and cookie-based sessions. CRUD data is stored in PostgreSQL. Express sessions use the default in-memory session store and reset when the server restarts.

## Run locally

Requirements: Node.js 20 or newer.

```sh
npm install
cp .env.example .env
# Set DATABASE_URL, SESSION_SECRET, ADMIN_EMAIL, and a strong ADMIN_PASSWORD in .env, and create the PostgreSQL database first.
npx prisma db update
npm run db:seed
npm run dev
```

The API listens on `http://localhost:5000` when using the included `.env`; otherwise `PORT` defaults to `3000`. Set `ADMIN_PASSWORD` to at least 8 characters before starting the server. Startup creates or promotes the account configured by `ADMIN_EMAIL` to the `admin` role and updates its password hash from `ADMIN_PASSWORD`. The same bootstrap can be run manually with `npm run db:admin`. For a compiled run, use `npm run build` and `npm start`.

`npm run db:seed` is optional sample data only; it does not create or change the admin. For a new account, use `POST /api/auth/register`; it assigns the `staff` role and signs the user in.

## Sessions

Register at `POST /api/auth/register` with a name, email, and password to create a staff account and sign in, or sign in at `POST /api/auth/login`. Both create a signed session cookie named `restaurant.sid`; it is `HttpOnly`, `SameSite=Lax`, and uses `Secure` when `NODE_ENV=production`. Send that cookie with subsequent requests. `POST /api/auth/logout` destroys the session, and `GET /api/auth/me` returns the signed-in user. User passwords are hashed using Argon2id and password hashes are never returned by the API.

## Endpoints

For request and response schemas, validation rules, status codes, and the full endpoint reference, see [API.md](API.md).

All endpoints except health and authentication require a valid session cookie.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | API status |
| POST | `/api/auth/register` | Register a staff account and create a session |
| POST | `/api/auth/login` | Create session; JSON `{ "email", "password" }` |
| POST | `/api/auth/logout` | Destroy session |
| GET | `/api/auth/me` | Current session user |
| GET, POST | `/api/users` | List or create users |
| GET, PUT, DELETE | `/api/users/:id` | Read, update, or delete a user |
| GET, POST | `/api/categories` | List or create categories |
| GET, PUT, DELETE | `/api/categories/:id` | Read, update, or delete a category |
| GET, POST | `/api/menu-items` | List or create menu items |
| GET, PUT, DELETE | `/api/menu-items/:id` | Read, update, or delete a menu item |
| GET, POST | `/api/orders` | List orders or create an order |
| GET, PUT, DELETE | `/api/orders/:id` | Read, update, or delete an order |

IDs are integer primary keys generated by PostgreSQL. Filter menu items by category with `GET /api/menu-items?categoryId=1` (use the ID returned by `GET /api/categories`).

Create an order with one or more menu items:

```json
{
  "customerName": "Avery Chen",
  "items": [
    { "menuItemId": 1, "quantity": 2 },
    { "menuItemId": 5, "quantity": 1 }
  ]
}
```

Order responses include each menu item, saved unit price, line total, and order total. Category deletion is rejected while menu items reference it; menu item deletion is rejected while orders reference it. Invalid input returns `400`, missing records return `404`, duplicate/conflicting data returns `409`, and unauthenticated requests return `401`.

## Sample API flow

```sh
curl -i -c cookies.txt -H 'Content-Type: application/json' \
  -d '{"name":"Sam Rivera","email":"sam@example.com","password":"sample-pass-123"}' \
  http://localhost:3000/api/auth/register

curl -b cookies.txt http://localhost:3000/api/menu-items
```

The Prisma contract defines `users`, `categories`, `menu_items`, `orders`, and `order_items`, with primary/foreign keys and uniqueness. `npx prisma db update` creates or updates those tables from the contract, and `npm run db:seed` inserts sample rows through ORM queries. `database/schema.sql` is provided as a readable SQL reference for presentations. Use the collection in `postman/restaurant-management-api.postman_collection.json` to explore the endpoints; Postman retains the registration/login session cookie.
